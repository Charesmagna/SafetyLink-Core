1. Native Dispatch & Channel Logs Native P0

Discrete logging for every native fallback dispatch channel (USSD, SMS, Direct Call, Backend Sync):

  • USSD Dispatch: Dialed via TelephonyManager/ACTION_CALL (*134*...# or emergency string) with timestamp, response string, and session ID.
  • Multipart SMS: Dispatched via SmsManager with separate BroadcastReceivers for SENT and DELIVERED states.
  • Voice Call: Dispatched via ACTION_CALL (falling back to ACTION_DIAL if permission restricted), logged as INITIATED, FAILED, or UNAVAILABLE.
// Canonical Log Entity Model
data class DispatchLogEntry(
    val incidentId: String,
    val channel: String, // "USSD" | "SMS" | "CALL" | "CLOUD"
    val recipient: String,
    val payload: String,
    val status: String,  // QUEUED, SENT, DELIVERED, INITIATED, FAILED
    val timestamp: Long,
    val radioCellId: String? = null
)

4. System-Wide Floating SOS Bubble WindowManager

A floating movable bubble (Chat Head style) that persists over any third-party app or home screen:

  • Requires SYSTEM_ALERT_WINDOW permission with in-app check and settings redirect.
  • Touch listener handles dragging across screen borders and snapping to edges.
  • Single tap opens 10-second disarm countdown overlay; double-tap executes instant direct dispatch.
  • Toggleable anytime in Settings via useAppStore().setFloatingBubbleEnabled(...).

5. Configurable Dispatch Engine UI / Engine

A user-customizable emergency dispatch rule manager with fine-grained channel presets:

6. Open Integrations Hub Connectors

A self-serve connector ecosystem where individual users or organizations plug in their own API credentials:

  • Twilio: Account SID, Auth Token, From Phone Number (Auto-tests balance & validates active voice/SMS capabilities).
  • VAPI / Bland.ai: Assistant ID & API Key for automated voice phone calls and interactive AI triage.
  • Africa's Talking: Username & API Key for localized African SMS & USSD gateways.
  • Infobip: Base URL & API Key for global multi-channel delivery.
  • Cloudinary / S3 / R2: Custom bucket & credentials for off-device evidence storage.
  • Dynamic Requirements: Auto-renders required fields (e.g., Sender ID, Line Number, Webhook Secret) and activates immediately upon testing success.

7. Local Database & Continuous Google Drive Synchronization Sync / Sheets

Continuous client directory maintenance, offline caching, and automated Google Drive document update loop:

  • Local User Database: Stores profile information, emergency contacts, medical passport data, assigned iTAG BLE UUIDs, subscription tier, and GPS coordinates.
  • Continuous Delta Polling: A background polling worker detects newly registered or updated users and synchronizes records without manual refresh.
  • Google Drive Exporter: Authenticates via OAuth Client ID to write to a designated Google Sheet / Document. Rather than spawning new documents on every push, it continuously appends and updates the existing document with timestamped roster changes and incident telemetry.
// Google Drive Continuous Sync Workflow
async function syncRosterToDrive(spreadsheetId: string, users: UserProfile[]) {
  const values = users.map(u => [
    u.id, u.fullName, u.phone, u.role, u.orgCode, 
    u.lastLocation?.lat || 'N/A', u.lastLocation?.lng || 'N/A',
    new Date(u.lastLocation?.timestamp || Date.now()).toISOString()
  ]);
  await gapi.client.sheets.spreadsheets.values.update({
    spreadsheetId,
    range: 'SafetyLink_Roster!A2:H',
    valueInputOption: 'USER_ENTERED',
    resource: { values }
  });
}
